# 양자 블록 작곡기 · 펄스 시퀀서

구현: `src/js/instrument/composer.js`(UI), `src/js/instrument/qresults.js`(결과), `src/js/quantum/sim.js`(시뮬레이터), `src/js/quantum/pulses.js`(펄스 컴파일).

## "코딩"의 정확한 아날로그 표현

| 표현 | 뜻 | 이 벤치에서 |
|---|---|---|
| 양자 회로 작성 (composing) | 게이트를 큐비트 선 위에 배치. IBM 도구 이름이 Composer(작곡기) | 블록 그리드 |
| **펄스 시퀀싱 (pulse sequencing)** | 각 게이트를 정해진 시각·진폭·위상·주파수의 마이크로파·플럭스 펄스로 재생 | "펄스 시퀀스" 패널, 오실로스코프 `큐비트 펄스` 프리셋 |
| 패칭 (patching) | 아날로그 컴퓨터를 패치 코드로 배선해 프로그래밍하던 옛 방식 | 블록을 꽂는 조작감의 원형 |
| 해밀토니안 프로그래밍 | 어닐링·아날로그 양자 시뮬레이션에서 에너지 함수와 그 시간표를 정하는 방식 | (다루지 않음) |

**결론**: 블록 배치 자체는 "양자 회로 작성(작곡)"이고, 그것이 하드웨어에서 실행되는 아날로그 실체는 "펄스 시퀀싱"입니다.

## 게이트 → 펄스 대응

| 블록 | 하드웨어 동작 | 시간 |
|---|---|---|
| X, Y | 구동선 π 가우시안 (위상 0° / 90°) | 40 ns |
| √X | π/2 가우시안 | 40 ns |
| RX(θ), RY(θ) | 진폭 θ/π 가우시안 | 40 ns |
| H | 가상 Z90 · √X · 가상 Z90 | 40 ns |
| Z, S, T, RZ(θ) | **가상 Z**: 펄스 없이 이후 펄스의 위상 기준을 돌림 | 0 ns |
| CZ, CP(θ) | 제어 큐비트 플럭스 펄스 (평탄 펄스) | 200 ns |
| CX | H(대상) · CZ · H(대상) | 280 ns |
| SWAP | CX × 3 | 840 ns |
| M | 판독 톤 1 µs + ADC 적분 창 | 1 µs |
| RST | 판독 + 결과가 1이면 π 펄스 | 1.2 µs |

비인접 쌍(결합 맵 기준)의 2큐비트 게이트에는 SWAP 라우팅이 붙습니다.

## 시뮬레이터

- 최대 5큐비트 상태벡터(32 진폭). 비트 순서는 Qiskit과 같습니다(Q0이 최하위 비트, 문자열은 Qn…Q0).
- 노이즈는 양자 궤적 128개로 계산합니다. 하드웨어 모델(`hardware.js`)의 값을 그대로 씁니다.
  - 결맞는 오차: 구동 진폭 오보정(k ≠ 1)과 이조(δ)로 회전축과 회전각이 틀어짐
  - 게이트 오류: 1Q 후 p1, 2Q 후 p2 확률의 무작위 파울리
  - 결맞음 손실: 층마다 T1 진폭 감쇠 점프 + Tφ 위상 반전
  - 열적 들뜸 초기 상태, 판독 오류(비트 반전)
- 충실도는 측정 분포와 이상적 분포의 고전 충실도 (Σ√(p·q))²입니다.

## 실제 QPU에서 실행

1. 작곡기에서 **OpenQASM** → **복사**
2. IBM Quantum(quantum.cloud.ibm.com)의 Composer에서 OpenQASM 편집기에 붙여 넣기
3. 실제 백엔드를 골라 실행하고, 결과 막대그래프를 벤치의 "측정 결과"와 비교하기

예제 회로의 QASM은 [presets.qasm](presets.qasm)(자동 생성)에 있습니다. 클라우드 QPU의 결합 구조는 벤치(T자형)와 다르므로, 클라우드 쪽 트랜스파일러가 라우팅을 다시 합니다.
